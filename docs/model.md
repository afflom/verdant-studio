- **REQ-SELF-HOSTED** (afflom): Verdant Studio is implemented in Verdant Studio: its entire production, every part of its model, is made in Verdant Studio, so that its UI is beautiful, refined, cohesive, illustrative and best-in-class for each part's domain use.

- **REQ-ENGINE-FIDELITY** (afflom): Verdant Studio is designed and implemented to the highest specification of graphical detail and of visual and auditory immersion. Verdant Engine provides it with ultra-high-definition rendering of the highest quality and resolution and multimodal fidelity equal to the most high-end gaming systems.
- **REQ-ENGINE-RUNTIME-ONLY** (afflom): The Verdant Studio model inside verdant-engine is a contrived proof of concept. Verdant Studio binds only Verdant Engine's runtime capabilities and takes no construct, design or view from that proof of concept.

- **REQ-SELF-HEALING** (afflom): When an operation of the Verdant Studio API fails, the API records the failure in the model as an error that holds its exact refusal and the requirement it breaks, restores service by its own operations, derives the repair from the error as the Verdant Engine Observer derives its refinement agenda, and dispatches that repair through the App behind the same self-verification check plus a regression vector built from the error, so that the bug is fixed by the API itself in normal operation and cannot return, and nothing reaches main red.
- **REQ-PRISM-GENERATION** (afflom): Verdant Studio exists to generate applications and their multimedia, and its pipelines implement the production process that creates its content, a Verdant Prism: one media type, or a bundle of media types that makes up an application, including the WebAssembly that runs in a browser or a WebAssembly runtime. A Verdant Prism is created from a single word or sentence; Verdant Studio specifies a subset of the Prism from that seed, and the Prism's generators generate all its other facets, because every part of Verdant Studio has a generator for its multimedia, such as a song, a soundtrack, cover art or a logo. The user may tune as few or as many features as they choose until all of the Prism's features meet its intent. The generators always define the Prism to ultra-high precision through the coherence of all of Verdant Studio's models, so that every part is defined consistently to its full expression, and this is verified by prompting Verdant Studio and checking that every artifact has its correct media type and the highest fidelity.
- **REQ-ENGINE-MUSIC** (afflom): Verdant Engine composes music from a Verdant Prism's features as MIDI 1.0 messages, deterministically, refusing invalid features by name, so that a song or a whole soundtrack of the Prism can be generated (REQ-PRISM-GENERATION).
- **REQ-ENGINE-AUDIO-FILE** (afflom): Verdant Engine encodes the audio it synthesizes as Broadcast Wave Format files, bit for bit deterministic, so that every audio artifact of a Verdant Prism has a declared media type (REQ-PRISM-GENERATION).
- **REQ-ENGINE-RASTER-IMAGE** (afflom): Verdant Engine encodes the frames it renders as PNG images at their full rendered resolution and colour depth, bit for bit deterministic, so that raster artwork of a Verdant Prism, such as its cover art, has a declared media type (REQ-PRISM-GENERATION).
- **REQ-ENGINE-VECTOR-IMAGE** (afflom): Verdant Engine renders vector artwork as SVG documents, deterministically, so that vector artwork of a Verdant Prism, such as its logo, has a declared media type (REQ-PRISM-GENERATION).
- **REQ-PLAYER-FEEDBACK** (afflom): Players give feedback from inside the Verdant Prism they play, through its player feedback forms, and creators may occasionally prompt their players for feedback on new features; a player signs in to Verdant Studio only to make their own game. Verdant Studio catalogs all feedback, masks it, and analyzes it together with other feedback, so that features are distilled into future releases from consensus rather than single interests, while a single piece of feedback that merits action without consensus, such as a bug or a special request that would add significant value to the referenced game or app, is identified and actioned on its own. The generative acceleration that drives Verdant Studio's automations also drives this loop, reducing the time from feedback to publishing.
- **REQ-SELF-RUNTIME** (afflom): Verdant Studio runs its own processes in its own runtime rather than in GitHub pull requests and Actions, as Verdant Engine's model keeps GitHub only as an origin mirror of its self-hosted release: the Verdant Studio API runs its operations, the studio check, admission, the certified Lean export and the scheduled Verdant Engine tracking inside that runtime, keeps the model's revision history there with W3C PROV-O lineage, cuts a SemVer release only when every gate passes on the current revision, and then publishes the release to GitHub as the Verdant Studio GitHub App by pushing its commits, tag, build provenance and metadata and deploying the built site to GitHub Pages, with no GitHub Actions workflow of its own. - **REQ-PROJECT-INSTANCE** (afflom): Every Verdant Studio project is its own isolated instance with its own strong identity as a stand-alone Verdant Engine application, a Verdant Prism, and Verdant Studio is one such project that manages itself while keeping its own project details inside its own project. A person's data and Verdant Studio instances are private to their Prism ID unless they share their content.
